# 共享语音输入

Chat（旧单人）、Meeting 与 Desktop 共用 `pages/voice.html` 内唯一的
`SherpaSpeechRecognition`。页面只持有草稿、当前会话和发言对象；生成、发送和
取消仍由页面原来的会话逻辑执行。TTS 播放归属没有迁移。

## 使用

1. 程序启动后自动加载 ASR 并进入待命，不需要点击启动。首次麦克风授权在可见页面完成，临时授权流立即释放。
2. 默认按住反引号说话，松开结束；也可以按住界面按钮，或选择自由麦。
3. 默认自动发送关闭、角色说话闭麦开启、语音输入打断开启、后台语音开启；已有后台语音开关偏好继续保留。
4. 游戏中使用：选择会话和角色即可，后台目标自动判断，不再手动绑定。需要直接交谈时开启自动发送。按键模式只监听快捷键，按下才采音。
5. 通过“关闭麦克风”停止采集，切换回按键说话或自由麦自动恢复。
6. 普通桌宠不显示对话面板；Galgame 顶栏的“最小化到后台”保留舞台、对话和语音接收，通过任务栏或托盘恢复。

## 路由与数据

- 优先使用有焦点且能输入的对话页面；没有有效前台目标时，只有开启后台语音
  才按 Galgame（Desktop 舞台）→ Meeting → Chat 顺序选择仍在运行的有效页面。
- 每句话在按键按下或 VAD 人声开始时锁定页面实例、会话、角色。结果不会改投
  后来激活的页面。关闭、刷新或切换原会话后，结果进入待处理语音，需主动恢复。
- 自动发送关闭时追加草稿；已有草稿时，即使自动发送开启也只追加。页面无法
  提交时保留草稿，不抢焦点，不打开窗口或 Galgame。
- 草稿按页面/会话/角色持久化，交付编号随草稿保存以去重。宿主在交付前先保存
  待处理结果，收到接收确认后移除。恢复的文字只填草稿，不自动发送。
- 所有语音设置跨窗口同步；多人队列的打断按会话限定，不取消另一个会话。

## 生命周期

- Tauri 命令 `ensure_voice_host` 串行创建隐藏窗口，通信使用 Tauri 事件。
  唯一宿主注册全局快捷键，业务页面不注册。窗口焦点来自 Tauri 原生事件。
- 浏览器开发自动挂载隐藏宿主 iframe，使用 BroadcastChannel 和 Web Locks 单实例锁；
  每页候选宿主排队接管，关闭当前宿主页后继续可用。浏览器不支持操作系统全局按键。后台标签调度受浏览器限制，
  游戏陪玩应使用桌面版。
- 所有窗口共用 WebView2 后台计时参数，保持隐藏宿主及最小化页面心跳。
- 按键松开会取消未完成的开麦；异步权限或 worklet 加载迟到时不能重新开麦。
  VAD 消息带录音编号，旧会话事件不能触发新会话。录音上限 60 秒，超限只保留草稿；
  识别另设 60 秒超时，避免长期卡在识别状态。
- 角色实际播放状态按播放编号与角色维护。自由麦默认暂停；按键可以接管并打断。
  播放完成、取消、断线和超时均解除闭麦状态。
- Windows 输入桌面锁定、系统暂停后恢复、麦克风断开会停止语音。锁屏/暂停会关闭
  后台语音，需要主动重新开启。非 Windows 的系统锁屏检测尚未接入原生通知；
  计时中断仍会触发暂停保护。

## 验证

`VoiceInputRuntime.test.ts` 覆盖路由、后台目标、快按、迟到结果、多角色闭麦、
打断、时长上限与手动恢复。`SherpaSpeechRecognition.test.ts` 覆盖异步权限与
worklet 加载期间取消后的资源释放。`voiceDraft.test.ts` 覆盖持久化去重与会话隔离。

启动 Vite 后执行：

```sh
node scripts/verify-voice-input.mjs http://127.0.0.1:5173
```

这是浏览器集成检查，使用合成 ASR 结果，不采集真实麦克风、不调用 LLM。
真实隐藏 WebView 的麦克风授权、游戏前台全局按键、锁屏及物理设备拔插，仍需
在重新构建的桌面版中验收，不能由合成音频测试替代。
