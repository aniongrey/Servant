# 舞台光照与阴影

## 本次修正

MMD 加载器使用独立的着色器光照公式，不自动读取 Three.js 场景灯。`mmdLighting.ts` 将场景主光方向、颜色、强度同步到加载器的光照 uniform，并让环境补光控制原材质的 ambient 分量。主光以界面默认 3.0 对应 MMD 原始 154/255 强度校准，避免直接把 3.0 填进 MMD 公式造成过曝。反复预览、取消、应用不会累计乘暗材质；材质重新编译后也保留当前补光。

VRM 继续使用场景灯与 MToon。修改渲染参数会主动刷新共享画布中对应角色的缓存。

coco小熊这类使用 `KHR_materials_unlit` 的 VRM 原本完全忽略场景灯。加载器在 MToon 兼容转换完成后，将剩余 unlit 材质交给 glTF 的受光材质路径，保留贴图、透明度与已有表面参数；未指定金属度/粗糙度时使用非金属、粗糙表面。可用 `node scripts/verify-lighting.mjs E:/airi/VRM/coco小熊.vrm` 验证本地 VRM，或传入 `testmodel` 验证内置 MToon VRM。

验证：`npx vitest run src/character/mmd/mmdLighting.test.ts`；`node scripts/verify-lighting.mjs` 使用真实 PMX 模型，通过舞台灯光按钮比较明亮室内与夜景的实际画布像素，并验证应用保存。背景图片本身不受角色灯光影响，背景亮度是单独的图片参数。

## 方向设计建议（尚未实现为控件）

以背景里看得见的窗户、太阳、台灯为依据，给整个舞台统一一盏主光。同场角色保持一致，角色单独调整材质或少量亮度，避免每个人像站在不同房间。

- 主光方向用“左右方位 + 高度角”，不要直接让用户输入 XYZ。可提供左前上、右前上、正前、逆光预设；起点使用前侧约 35°、高度约 45°，再按背景调整。
- 补光负责保住暗部细节，强度明显低于主光。日景较柔和，夜景降低补光以保留明暗对比；不要用很强的补光把主光方向抹平。
- 接触阴影只负责让脚落地：脚边短、小、软，起跳时变淡、变宽，不随着主光左右平移。
- 落地投影由同一个主光方向计算：左上来光，影子向右后方；光越低，影子越长。影长与 `角色离地高度 / tan(光源高度角)` 相关，需要上限避免接近地平线时无限拉长。

## 现有阴影的限制与实施顺序

目前脚下是平面接触阴影，背后是 CSS `drop-shadow`。后者是屏幕上的人形贴影，无法表达地面透视；共享渲染器隐藏了各角色的独立 canvas，所以独立 canvas 上的 CSS 投影也不会显示。不能通过调它的左右偏移来冒充地面投影。

建议先做统一的场景主光方向，再在共享渲染阶段添加对应的投影；不要把阴影贴到不可见的占位 canvas 上。Galgame 默认保留接触阴影、关闭人形屏幕投影。若背景确实有可对齐的地面，再加透明接影平面，匹配地平线和主光；纯头像/半身画面不需要地面投影。2D 背景没有深度，不能自动让影子绕过桌子、墙角，复杂遮挡需要额外场景几何或遮罩。

验收应覆盖主光左右切换、低角度长影、补光为零、跳跃接触阴影、多人方向一致，以及 VRM/MMD 的实时预览、取消和保存。方向控件与真实投影属于后续功能，本次只修复灯光参数不生效。
